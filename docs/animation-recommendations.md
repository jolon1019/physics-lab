# 动画库选型与效果推荐台账

> 用途：记录项目可引入的动画/可视化库评估结论，以及「后续实验若需要更好表现力时」的推荐清单。
> 维护方式：每评估一个新库或落地一个效果，就在此文档追加/更新对应条目；横线分隔的「推荐登记表」随实验推进填写。

---

## 1. 项目现状（基线）

- 技术栈：Vue3 `<script setup>` + Vite + Pinia；电路图用 **SVG** 渲染，仿真量（电流/电压/电子流）用 **canvas 2D + rAF** 物理循环驱动。
- 已有动画能力：
  - `circuit.js` 的 `animatedBranches` / `pointOnPolyline` → 电子流沿导线折线跑。
  - `drawCircuitIcon.js` / `boardBg.js` → 灯泡辉光、背景绘制。
  - `CircuitBuildCanvas.vue` → 导线避让布线、端子高亮（`.term.pending`/`.term.armed`）。
- 关键约束：**物理量（电流、电压、位移、明暗）必须跟仿真 solver 每帧走，不能用补间硬塞**，否则会和物理打架。

## 2. anime.js 评估结论

- 来源：<https://github.com/juliangarnier/anime>（v4.5.x）
- 许可：**MIT，完全免费、可商用**，无付费墙。
- 引入方式：ESM，`import { animate, stagger } from 'animejs'`；体积约 10–17KB gzip，可 tree-shake，无负担。
- 能驱动的目标：CSS 属性、SVG 属性（含 `stroke-dashoffset` 描边绘制）、DOM 属性、普通 JS 对象（供 canvas 读取）。框架无关，在 `onMounted`/`watch` 里调用即可。

### 2.1 适合用 anime.js（润色层 / 表现层）

| 场景 | 现状 | 用 anime.js 的做法 | 收益 |
|---|---|---|---|
| 电路图「画出来」 | SVG 符号一次性渲染 | `stroke-dashoffset` 沿 `getTotalLength()` 描边绘制 | 教学感强，直观展示「电路怎么连」 |
| 端子状态提示 | `.term` 静态色 | 绿/黄高亮做 pulse / 呼吸缓动 | 比纯色更易懂哪个可连 |
| 元件入场 | 拖入即出现 | `stagger` 缩放+淡入 | 一排元件依次出现，有层次 |
| 电表指针 | rAF 跳变 | 缓动到目标读数 | 指针顺滑、不抖 |
| 开关 / 面板 / 标签过渡 | 直接切换 | 切换动画、淡入淡出 | UI 更精致 |

### 2.2 不适合用 anime.js（继续用 rAF 物理循环）

- 电子流速度、灯泡明暗、沿导线的辉光 —— 由电路解算结果驱动，不是「到某点的补间」。
- 任何物理仿真（抛体、摆、MNA 求解后的连续量）的**数值推进本身**。

### 2.3 集成边界（铁律）

- 两套系统**不抢同一属性**：物理量归 rAF，装饰/过渡归 anime.js。
- 若想要「Vue 声明式」动画，可备选 `@vueuse/motion`；但 anime.js 对 SVG 描边 / 时间线更强。

### 2.4 当前决策

- **值得引入**。已正式引入（v4.5.0，2026-08-16），首个落地案例：通电线圈在磁场中转动（见登记表第 2 行）。

## 4. 其它候选库（未评估，按需再填）

- `@vueuse/motion`：声明式 Vue 动画，适合 UI 微交互。
- `pixi.js`（已在 `node_modules`）：WebGL 粒子/大量精灵，适合「百万电子流 / 火花 / 光晕」等重特效，但本项目电路规模小，暂不需要。
- `three.js`（已在 `node_modules`，**已评估并落地**）：3D 实验场景首选。e-coil-rotation 已用它做真 3D 旋转演示（OrbitControls 可拖拽）。后续凡需要「立体空间关系 / 真实转动 / 3D 场线」的实验（如立体光路、磁场分布、杠杆/滑轮 3D）优先用它。
